# 엑셀 정리기 — 3주차

## 쓰기 전에

1. **파일은 브라우저를 떠나지 않습니다.** 정리는 모두 이 브라우저 안에서 합니다. F12 → Network 탭을 연 채 파일을 넣어 보면, 파일이 밖으로 나가는 요청이 없는 것을 직접 확인할 수 있습니다.
2. **이 정리기가 못 하는 것:** 처방에 없는 것은 고치지도 표시하지도 않습니다. 출장비정산 정답 대조에서 처음 놓친 22건 중 15건(출장일 빈칸 · 박수 음수와 너무 큰 값 · 교통비 음수 · 부서의 같은 뜻 다른 이름)은 처방을 더해 고치거나 표시하게 했습니다. 남은 7건은 **같은 줄이 덮어쓴 원래 줄**이라 되살리지 못합니다. 또 **표시한 값(빈칸 · 튀는 값 · 칸 사이 모순)은 고치지 않습니다** — 진짜 값은 사람이 확인해야 합니다. 처방 표에 없는 새 이름이 들어오면 그대로 둡니다.
3. **처방을 바꾸려면 `rules/<파일 이름>.json`을 고칩니다.** 코드는 고치지 않습니다.

엉망인 엑셀·CSV를 끌어다 놓으면 **증상을 진단**하고, **내가 정한 처방 가운데 켠 것만** 적용해 새 정리본을 만들고, **원본과 정리본을 나란히** 보여 줍니다.
**파일은 이 브라우저를 떠나지 않습니다.** 서버가 없습니다.

## 흐름

1. **파일** — 끌어다 놓기 · 고르기 · 예시 파일
2. **진단** — 빈칸 · 중복 · 표기 불일치 · 형식 불일치 · 이상치 후보 · 칸 사이 모순(처방 파일에 정한 규칙만). 유형 필터와 찾기. 아무것도 고치지 않는다
3. **처방 선택** — 처방 파일을 «자동 정리(모양만) · 사람이 정한 값 바꾸기 · 줄 지우기 · 검토 표시» 넷으로 나눠 하나씩 켜고 끈다. 처방마다 대상 칸 · 바꾸는 방식 · 이유 · 예상 영향. 켠 처방은 이 브라우저에 저장하거나 처방 파일로 내려받아 다음 파일에 다시 쓴다. 두 처방이 같은 칸을 다르게 다루면 실행을 막고 알린다
4. **확인 후 정리 → 전후 비교** — 원본 | 정리본을 나란히. 바뀐 칸(빨강) · 검토 필요(노랑) · 지운 줄(회색). 바뀐 칸을 누르면 전 · 후 값, 처방, 이유. 변경 기록 · 검토 필요 · 제외된 줄 · 정답과 대조 탭
5. **내려받기** — `정리본.xlsx` · `변경기록.xlsx`(바뀐 칸 · 지운 줄 · 적용한 처방 · 정보) · `검토필요목록.xlsx`, CSV 도 가능

### 출장비 규정 확인 (선택)

처방 파일에 `policy_fields`가 있으면 나타난다. **데이터 형식 정리와 비용 적정성 판단은 별개**다.

- 1순위 회사 규정 → 2순위 회사가 **공식 채택한** 외부 기준(예: 미국 GSA Per Diem, `adopted: true`이고 요율을 규정 파일에 적었을 때만) → 3순위 **판단 불가 — 검토 필요**
- 기준 금액을 추정하지 않는다. 원본 금액을 바꾸지 않는다. 한도를 넘어도 «위반»이 아니라 «한도 초과 — 검토 필요»
- 규정 파일은 사용자 파일처럼 이 브라우저에서만 읽는다. 외부 기준을 인터넷에서 가져오지 않는다 — 출처 · 기준 연도 · 지역 · 기간을 규정 파일에 적는다
- 통화가 없으면 화면에서 정한다. 환율 · 환산 기준일이 없으면 판단 불가. 규정 양식은 화면의 «양식 내려받기»
- **회사 규정 파일은 이 저장소에 없다.** 규정 없이는 적정성을 판단하지 않는다

## 파일

|---|---|
| `rules/*.json` | ★ **처리 규칙** — 무엇을 어떻게 바꿀지, **왜** 그렇게 정했는지. **사람이 정한다** |
| `clean.js` | 진단(규칙 없이 증상 찾기) · 규칙 적용 · «두 번 돌려도 같은가» · 정답 대조 |
| `app.js` · `index.html` · `style.css` | 화면 |
| `lib/xlsx.full.min.js` | 엑셀 읽기 · 쓰기 (SheetJS Community Edition 0.20.3, Apache 2.0 — `lib/LICENSE-sheetjs.txt`) |
| `lib/PretendardVariable.woff2` | 글꼴 Pretendard 1.3.9 (SIL OFL 1.1 — `lib/LICENSE-pretendard.txt`). 외부에서 불러오지 않는다 |
| `data/` | 예시 파일 세 개 — 상담이력 · 교육이수로그 · 출장비정산 (모두 만들어낸 데이터) |
| `CLAUDE.md` | 이 프로젝트에서 늘 지킬 것 (저장소에만, 배포 제외) |
| `tools/` | 정답 · 확인 도구 — **저장소에도 배포에도 올리지 않는다** (`.gitignore` · `.vercelignore`) |

## 규칙 파일의 모양

```json
{
  "columns": {
    "채널":   {"trim": true, "map": {"유선": "전화"}, "why": "같은 채널을 여러 이름으로 적었다"},
    "상담시간": {"number": true, "rescale": {"over": 180, "divide": 60}, "why": "…"},
    "이수시간": {"number": true, "missing": "flag", "range": {"min": 0, "max": 400, "action": "flag"}}
  },
  "cross_checks": [{"label": "이수 0시간인데 수료", "when": [["이수시간", "==", 0], ["수료여부", "==", "수료"]]}],
  "duplicates": {"action": "drop", "why": "모든 열이 같은 행은 하나만"}
}
```

- 날짜 칸에 `"unparsed": "flag"`를 더하면 읽지 못한 날짜(연도 두 자리 등)를 고치지 않고 표시합니다.
- `cross_checks`의 조건은 `==` · `!=` · `>` · `<` · `blank`. 한 칸만 넣으면 한 칸 검사(예: 교통비 `<` 0)가 됩니다.

적용 순서는 열마다 `trim → map → blank_to → strip_units → number → date → rescale → missing/range`, 그다음 두 열 검사, 마지막에 중복입니다.

## 확인한 숫자

headless Chrome 에서 이 화면을 실제로 눌러 확인한 값입니다 (2026-11-14, 처방 전부 켬). «바뀐 칸»은 정리본에 남은 줄만 셉니다 — 지운 줄은 «지운 줄»에 따로.

| 파일 | 줄 | 지운 줄 | 바뀐 칸 (줄) | 검토 표시 줄 | 두 번 돌려도 같은가 | 원본 그대로 |
|---|---|---|---|---|---|---|
| 출장비정산.xlsx | 201 → 194 | 7 | 18 (18) | 23 | 같음 | 그대로 |
| 상담이력.xlsx | 1,542 → 1,512 | 30 | 2,779 (1,456) | 0 | 같음 | 그대로 |
| 교육이수로그.csv | 120 → 120 | 0 | 73 (59) | 17 | 같음 | 그대로 |

- 화면이 불러온 주소는 모두 같은 사이트(`rules/` · `data/` · `lib/`)뿐이었다. 사용자 파일을 보내는 요청은 없다

- 출장비정산 정답 대조 (만든 방법의 섞은 것 47건): **고쳤다 18 · 표시만 했다 22 · 놓쳤다 7**. 놓친 7건은 같은 줄이 원래 줄을 덮어쓴 것 — 원래 값이 파일에 없어 처방으로 되살릴 수 없다
- 출장비정산 마지막 줄(행202)은 만든 방법에도 정답에도 없는 합계처럼 보이는 줄 — 지우지 않고 빈칸 · 숙박비 초과로 표시한다
- 상담이력 · 교육이수로그의 정답 대조(1,482행 일치 · 상담시간 18행 어긋남)는 목업 때 확인한 숫자다. «바뀐 칸»은 쉼표만 뗀 것도 기록하게 바꿔서 예전 목업보다 많다

## 도구가 못 보는 것

- **뜻이 같은 다른 말** — «완료»와 «수료». 값 목록을 눈으로 봅니다
- **색으로만 표시된 정보**, 병합 셀, 머리글 두 줄, 시트 여러 개 — 파일을 한 번 열어 봐야 압니다
